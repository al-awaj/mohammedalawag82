# خطة التدريب والتسليم

## 1. التدريب

كل جلسة عملية على بيئة تجريبية (نفس الحزمة على خادم اختبار ببيانات اختبار معلنة كذلك، وبوابة دفع في وضعها التجريبي)، لا على الإنتاج.

| الجلسة | الجمهور | المدة | المحتوى | المرجع |
|---|---|---|---|---|
| 1. جولة المنصة | كل الفريق | 1.5 ساعة | رحلة العميل من البحث إلى الدفع والإلغاء على الموقع والتطبيق؛ رحلة صاحب الخدمة؛ الأدوار والصلاحيات؛ سجل التدقيق | `14-admin-guide.md` §1 |
| 2. الانضمام والخدمات | مشرفو الخدمات | 2 ساعة | مراجعة طلب بوثائقه (قبول، طلب معلومات، رفض)، مراجعة ونشر خدمة، الأنواع والحقول الديناميكية، الإيقاف | §2 |
| 3. الحجوزات والإلغاء | موظفو الحجوزات والدعم | 2 ساعة | البحث، التقويم، طلبات الإلغاء، الإلغاء الإداري، النزاعات حتى القرار | §2 |
| 4. المالية | الفريق المالي | 3 ساعات | التحويلات البنكية (المبلغ المتحقق، الاعتماد المنفصل)، الاستردادات بمبدأ العينين، المستحقات، التسويات (عادية ومرحلية)، المستندات، التقارير متعددة العملات، المطابقة وفحوص الاتساق | §2–§4، `05-financial-design.md` |
| 5. الإعداد | مسؤولو النظام | 2 ساعة | الدول والعملات وأسعار الصرف، الشروط، الإعدادات، مزودو الدفع (`secretRef`)، العمولات، قوالب الإشعارات، الموظفون والأدوار | `12-deployment.md` §5 |
| 6. التشغيل | فريق التقنية | 3 ساعات | النشر، التحديث، المراقبة، النسخ الاحتياطي، **تمرين استعادة فعلي**، الحوادث، تدوير الأسرار، CI | `12-deployment.md`، `13-operations.md` |
| 7. أصحاب الخدمات | أول دفعة من الشركاء | 1 ساعة (مسجلة) | التسجيل، السياسات، الخدمات، التقويم، الحجوزات، المستحقات | `15-provider-guide.md` |

**معيار إتمام التدريب**: كل متدرب ينفذ بنفسه سيناريو جلسته كاملًا على البيئة التجريبية (مثال للمالية: تحويل بنكي ← تأكيد ← إلغاء ← اعتماد استرداد من زميل ← تنفيذ ← إشعار الاسترداد في المستندات ← فحوص الاتساق صفر).

## 2. ما يجب أن يوفره المالك قبل الإطلاق

| البند | لماذا | أين يُستخدم |
|---|---|---|
| اسم المنصة والهوية (شعار، أيقونات، ألوان) | يظهر في الواجهات والتطبيق والمستندات | `BRAND_AR/EN`، `APP_NAME`، `apps/mobile/assets`، إعداد `documents.platform_name` |
| النطاقات الأربعة | HTTPS والتطبيق والويب هوك | `deploy/.env` |
| الخادم أو حساب الاستضافة (ويُفضّل قاعدة بيانات مُدارة مع PITR وتخزين S3 خاص) | التشغيل والنسخ | `12-deployment.md` §7 |
| تخزين خارجي للنسخ الاحتياطية | نسخة خارج الخادم | `13-operations.md` §2 |
| حساب مزود دفع لكل دولة (تجريبي ثم حي) | الدفع عبر المنصة | يُضاف محوّل المزود (`GatewayAdapter`) وسرّه |
| مزود SMS وبريد (وWhatsApp إن أريد) | التحقق والإشعارات | قنوات الإشعارات |
| حسابات Apple Developer وGoogle Play وExpo | نشر التطبيق | `12-deployment.md` §6 |
| الشروط والأحكام وسياسة الخصوصية المعتمدة قانونيًا لكل دولة | البند 66 | «الدول والعملات والشروط» |
| متطلبات الفوترة الإلكترونية الرسمية لكل دولة (إن وجدت) | توقيع الفواتير | المستندات الحالية HTML قابلة للطباعة |
| نسب العمولة وسياسات الاسترداد والتسوية المعتمدة | الإعداد المالي | «العمولات»، «الإعدادات» |

## 3. قائمة التسليم

- [x] الشيفرة كاملة في المستودع، مع سجل التزامات لكل مرحلة.
- [x] التوثيق: المتطلبات، المعمارية، قاعدة البيانات، الصلاحيات، التصميم المالي (`docs/01–05`)، تقرير الاختبارات (`11`)، النشر (`12`)، التشغيل (`13`)، دليل الإدارة (`14`)، دليل أصحاب الخدمات (`15`)، هذا الملف (`16`). توثيق الـ API التفاعلي على `/docs` في بيئات التطوير والاختبار (معطّل في الإنتاج عمدًا).
- [x] الاختبارات الآلية: الواجهة الخلفية (بما فيها الأمان والمالية والتزامن والتخزين والنسخ)، الحزم المشتركة، المتصفح، الحمل، واختبار الحزمة الإنتاجية مع تمرين استعادة بعد كارثة.
- [x] CI على كل طلب دمج (`.github/workflows/ci.yml`).
- [x] صور الإنتاج وملف Compose مع HTTPS تلقائي، ونسخ احتياطي واستعادة متحقق منها.
- [ ] مدخلات المالك في §2.
- [ ] الاختبار #36 على أجهزة iOS وAndroid فعلية (بناء `preview` من EAS) قبل النشر في المتاجر.
- [ ] ربط مزود الدفع الحي ومزود الرسائل لكل دولة واختبارهما في بيئتهما التجريبية.
- [ ] اختبار اختراق مستقل، ومراجعة قانونية للشروط.
- [ ] إطلاق تجريبي محدود (دولة واحدة، عدد محدود من أصحاب الخدمات) مع مراقبة يومية لفحوص الاتساق والإشعارات الفاشلة لأسبوعين، ثم الإطلاق العام.

## 4. ما بعد التسليم (موصى به)

- خرائط واختيار الموقع في الواجهات (الـ API يدعم البحث بالمسافة).
- الإشعارات الفورية على الجوال (القناة جاهزة في الخادم).
- محولات كشوف المطابقة بصيغ البنوك الأصلية (CSV/MT940).
- PDF موقّع على الخادم وفق الفوترة الإلكترونية لكل دولة.
- سياسة CSP صارمة للسكربتات (nonce)، ومراقبة أخطاء (مثل Sentry) ومقاييس (Prometheus).
