## 4. متطلبات غير وظيفية

- **الاتساق**: كل منع تعارض وكل عملية مالية تُفرض داخل قاعدة البيانات (قيود، Exclusion Constraints، معاملات، مفاتيح منع تكرار) وليس في الواجهة.
- **عدم التكرار (Idempotency)**: كل طلب إنشاء حجز/دفع/استرداد/تسوية يحمل `Idempotency-Key`؛ إشعارات المزود تُخزن بمعرفها الخارجي مع قيد فريد.
- **قابلية التدقيق**: سجل تدقيق append-only مفروض بمشغلات قاعدة البيانات؛ لا حذف للمعاملات المالية؛ التصحيح بقيود عكسية.
- **عدم تغيّر التاريخ**: السعر والعربون والعمولة وسياسة الإلغاء والشروط تُنسخ (snapshot) إلى الحجز عند إنشائه.
- **الأمان**: TLS، تجزئة كلمات المرور بـ scrypt، رموز وصول قصيرة العمر، رموز تحديث دوّارة مُخزنة كبصمة، تحديد معدل الطلبات، Helmet، تحقق من الملفات.
- **التدويل**: عربي RTL وإنجليزي LTR؛ النصوص القابلة للترجمة تُخزن JSONB `{"ar": "...", "en": "..."}` لإتاحة لغات جديدة دون تعديل المخطط.
- **الوقت**: كل الأوقات `timestamptz` بتوقيت UTC في القاعدة، وتُعرض حسب المنطقة الزمنية للدولة/المستخدم.

## 6. الافتراضات التي تحتاج اعتمادًا من مالك المنتج

لن تُنفذ أي معالجة مالية غير محددة قبل اعتمادها (البند 2-5). البنود التالية مفتوحة:

1. نسب العمولة الفعلية لكل دولة/نوع خدمة (النظام يدعم القواعد؛ القيم تُدخلها الإدارة).
2. شجرة الحسابات المحاسبية المعتمدة (مقترح في `05-financial-design.md` بانتظار الاعتماد).
3. الجهة التي تتحمل تكلفة الكوبونات في كل عرض (حقل إلزامي عند إنشاء العرض).
4. مزودو الدفع والرسائل لكل دولة.
5. سياسة إلغاء الحجوزات الفرعية عند إلغاء الطلب الرئيسي (الافتراضي: لا إلغاء تلقائي).
