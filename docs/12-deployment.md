# دليل النشر

> يغطي تشغيل المنصة في الإنتاج على خادم واحد بحاويات Docker، مع بدائل الخدمات المُدارة. كل ما هنا مُختبر بـ `deploy/smoke-test.sh` وفي CI.

## 1. المكونات

| الخدمة | الصورة | الدور |
|---|---|---|
| `postgres` | `postgres:16` | قاعدة البيانات (أو قاعدة مُدارة، انظر §7) |
| `migrate` | `events/api` | يطبّق الترحيلات ويزامن البيانات المرجعية ثم ينتهي؛ لا يبدأ الـ API والعامل إلا بعد نجاحه |
| `api` | `events/api` | الواجهة البرمجية (للواجهات والتطبيق وإشعارات بوابات الدفع) |
| `worker` | `events/api` | المهام المجدولة: انتهاء الحجوزات المؤقتة، التذكيرات، إرسال الإشعارات |
| `admin`, `provider`, `web` | `events/admin` … | لوحة الإدارة، لوحة أصحاب الخدمات، موقع العملاء |
| `caddy` | `caddy:2` | HTTPS بشهادات تلقائية، والخدمة الوحيدة المنشورة للإنترنت |
| `backup`, `create-admin` | `events/api` | مهام عند الطلب (`--profile ops`) |

الملفات في `deploy/`: `docker-compose.yml`، `Caddyfile`، `.env.example`، `secrets.env.example`، `smoke-test.sh`.

## 2. المتطلبات

- خادم Linux بـ 4 أنوية و8GB ذاكرة و80GB قرص SSD كبداية (اختبار الحمل في `docs/11-test-report.md` تم على ما يعادل ذلك)، وDocker Engine 24+ مع Compose v2.
- أربعة أسماء نطاقات تشير (A/AAAA) إلى الخادم: الموقع، لوحة الإدارة، لوحة أصحاب الخدمات، الـ API. المنفذان 80 و443 مفتوحان.
- بريد لإشعارات شهادات TLS.

## 3. الإعداد الأول

```bash
git clone <المستودع> events && cd events/deploy
cp .env.example .env && chmod 600 .env
cp secrets.env.example secrets.env && chmod 600 secrets.env
```

املأ `.env`:
- النطاقات و`ACME_EMAIL`.
- `BRAND_AR`/`BRAND_EN`: اسم المنصة (يُضمَّن في الواجهات وقت البناء).
- `POSTGRES_PASSWORD`: قيمة عشوائية طويلة (`openssl rand -hex 24`).
- `JWT_SECRET`: `openssl rand -base64 48`. **الـ API يرفض البدء في الإنتاج** بالقيم التجريبية، أو بأصول غير HTTPS، أو بكلمة مرور قاعدة التطوير، أو مع تعطيل حد الطلبات.
- التخزين: `STORAGE_DRIVER=local` (حجم `storage` على الخادم) أو `s3` مع حاوية **خاصة** (AWS S3، Cloudflare R2، DigitalOcean Spaces، Wasabi، SeaweedFS…). الملفات لا تُقدَّم أبدًا مباشرة من الحاوية؛ كل تحميل يمر عبر فحص صلاحيات الـ API.

ضع في `secrets.env` أسرار التكاملات، متغيرًا لكل تكامل باسم الـ `secretRef` الذي يُدخل في لوحة الإدارة (مثال: `PAY_MOYASAR_SA_SECRET=…`). المنصة لا تخزن هذه الأسرار في قاعدة البيانات ولا تعرضها.

- ملفات PDF (الفواتير والإيصالات والكشوف وعقد الحجز): تُطبع على الخادم بمتصفح Chromium (مضمّن في صورة Docker افتراضيًا؛ `--build-arg WITH_PDF=false` لاستبعاده). خارج Docker يُكتشف تلقائيًا Edge أو Chrome أو Chromium، أو حدد المسار في `PDF_BROWSER_PATH`. بدون متصفح تبقى نسخ الطباعة (HTML) متاحة ويعيد طلب PDF رسالة واضحة.

- تنبيهات الأخطاء: `ERROR_WEBHOOK_URL` (رابط Webhook لـ Slack أو Teams أو خدمة مراقبة) يستقبل أخطاء الخادم والمهام الخلفية غير المتوقعة دون أي بيانات شخصية، مرة كل 5 دقائق لنفس الخطأ.
- `BACKUP_DIR` يُعرض منه آخر نسخة احتياطية في «حالة النظام»، و`APP_VERSION` اختياري لعرض رقم الإصدار.

## 4. التشغيل

```bash
docker compose build             # أو اسحب صورًا جاهزة: IMAGE_PREFIX و IMAGE_TAG في .env ثم docker compose pull
docker compose up -d
docker compose ps                # كل الخدمات healthy، و migrate «exited (0)»
curl https://<API_DOMAIN>/ready  # {"status":"ready","checks":{"database":"ok","migrations":"ok","storage":"ok"}}
```

إنشاء أول مسؤول نظام (مرة واحدة):

```bash
docker compose run --rm create-admin --name "اسم المسؤول" --email admin@example.org --password '<كلمة مرور قوية>'
```

## 5. التهيئة التشغيلية الأولى (من لوحة الإدارة)

بالترتيب، وكلها مسجلة في سجل التدقيق:

1. **الدول والعملات والشروط**: تفعيل الدولة وعملتها ومنطقتها الزمنية، ونشر نسخة الشروط والأحكام (البند 66).
2. **الإعدادات**: مدة الحجز المؤقت (افتراضي 15 دقيقة)، مراجعة الخدمات قبل النشر، إظهار هوية أصحاب الخدمات، اسم المنصة في المستندات (`documents.platform_name`)، مهل الموافقة.
3. **التصنيفات وأنواع الخدمات** وحقولها الديناميكية.
4. **الصناديق والحسابات** لكل دولة وعملة (بوابة، بنك، نقد)، مع تعليمات التحويل البنكي.
5. **طرق ومزودو الدفع**: تكامل البوابة (الاسم + `secretRef`)، ثم «اختبار»، ثم التفعيل؛ ثم طرق الدفع عبر المنصة و/أو المباشر.
6. **العمولات**: قاعدة لكل دولة، ثم الاستثناءات (نوع خدمة، صاحب خدمة).
7. **الإشعارات**: قنوات الإرسال (SMS/بريد عبر `http_json` أو مزود) وقوالب الرسائل باللغتين.
8. **الموظفون والأدوار**: حسابات الفريق بأدوار محددة بالدولة؛ لا يُعطى `system_admin` إلا لشخصين على الأكثر.
9. عنوان الويب هوك لبوابة الدفع: `https://<API_DOMAIN>/v1/webhooks/payments/<معرّف التكامل>`.

## 6. التطبيق على المتاجر (iOS/Android)

في `apps/mobile` (يتطلب حساب Expo وحسابي Apple Developer وGoogle Play):

```bash
npm i -g eas-cli && eas login
APP_NAME="اسم التطبيق" APP_ID=com.company.app EAS_PROJECT_ID=<id> eas build --profile production --platform all
eas submit --profile production --platform all
```

عدّل `EXPO_PUBLIC_API_URL` في `eas.json` إلى نطاق الـ API، واستبدل الأيقونات في `assets/`. المعرّف `APP_ID` لا يتغير بعد النشر الأول في المتاجر. ملف `preview` يبني APK داخليًا للاختبار على الأجهزة قبل النشر (يُكمل الاختبار #36 على أجهزة فعلية).

## 7. بدائل مُدارة (موصى بها مع نمو الاستخدام)

- **قاعدة البيانات**: PostgreSQL 16 مُدارة مع النسخ المستمر واسترجاع نقطة زمنية (PITR)؛ احذف خدمة `postgres` وضع عنوانها في `DATABASE_URL` (تعديل `x-api-env` في ملف compose).
- **الملفات**: `STORAGE_DRIVER=s3` بحاوية خاصة مع الإصدارات (versioning) مفعّلة.
- **التوسع الأفقي**: يمكن تشغيل عدة نسخ من `api` و`worker` (المهام محمية بأقفال استشارية في قاعدة البيانات). عند تشغيل أكثر من نسخة من واجهات الويب يلزم توجيه ثابت للجلسة (sticky sessions) لأن منع تكرار تحديث الجلسة داخل الذاكرة.

## 8. التحديث والرجوع

```bash
git pull && docker compose build && docker compose up -d   # migrate يطبق الترحيلات الجديدة قبل بدء api
```

- **قبل كل تحديث**: `docker compose run --rm backup`.
- الترحيلات أمامية فقط وغير قابلة للتعديل بعد تطبيقها (فحص بصمة). الرجوع لإصدار سابق بعد ترحيل يغيّر المخطط يتم بالاستعادة من النسخة الاحتياطية (انظر دليل التشغيل)، لا بإعادة الصورة القديمة وحدها.
- `/ready` يعيد 503 ما دامت هناك ترحيلات معلقة، فلا يوجه موازن الأحمال حركة إلى نسخة بمخطط قديم.

## 9. اختبار الحزمة محليًا قبل النشر

```bash
cd deploy && docker compose build && ./smoke-test.sh
```

يشغّل الحزمة بأسرار مؤقتة وشهادات محلية، ويتحقق من الجاهزية عبر TLS، وترويسات الأمان على كل نطاق، والصفحة العامة، وإنشاء مسؤول وتسجيل دخوله عبر اللوحة، والنسخ الاحتياطي، ثم يزيل كل شيء.
